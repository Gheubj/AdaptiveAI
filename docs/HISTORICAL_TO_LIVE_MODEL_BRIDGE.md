# Historical-to-Live Model Bridge

Historical routing data trains and evaluates algorithms against immutable source identities and
past deployments. It does not authorize selecting a current provider alias. A live deployment must
separately satisfy exact/declared revision mapping, provider availability, modalities/tools/context,
privacy, price, latency, and eligibility rules.

Migration path:

1. retain historical candidates as `historical_only`;
2. register a current provider deployment without inheriting old outcomes;
3. link only through a reviewed time-bounded alias or exact revision;
4. import current capability/price/availability evidence;
5. run small targeted matched calibration under an approved budget;
6. validate shift and calibration before enabling experimental Auto routing;
7. abstain or use safe fixed/manual policy when the bridge is uncertain.

Future BYOK adapters supply deployments and runtime measurements; they do not rewrite historical
evidence or silently promote old benchmark scores.
